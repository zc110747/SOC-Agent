## Camera Agent 仿真与端到端验收（阶段 2，全部完成）

### 构建链路（关键坑）
- MSBuild 在 Bash/PowerShell 沙箱下直接崩溃（被安全策略拦截 / MSYSTEM 污染）→ 改用
  **Ninja + MSVC**，脚本 `scripts/build-msvc.ps1`（PowerShell，非沙箱模式运行）。
- 必须用 **VS 自带的原生 CMake/Ninja**（`D:\Software\vs\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin` 与 `...\Ninja`），
  不能用 MSYS2 的 cmake（会把 PATH 转冒号分隔，导致 cmd.exe 找不到 rc.exe）。
- 编译命令需显式 `-DCMAKE_CXX_COMPILER=D:/Software/vs/VC/Tools/MSVC/14.44.35207/bin/Hostx64/x64/cl.exe`，
  并补 `Windows Kits\10\bin\10.0.26100.0\x64`（rc.exe/mt.exe）进 PATH。
- 加 `/utf-8` 消 C4819（源码 UTF-8 被 MSVC 按 GBK 读）。零警告构建通过。

### 代码修复（4 处真实 bug）
1. **补 `src/rtsp/rtsp_publisher_gst.cpp`**：原缺失，实现 build_url/connect/disconnect/is_connected。
2. **GStreamer 管线**：`rtspclientsink` 是请求式 pad 且自带 RTP payloader，不能串 `rtph264pay`
   （链接失败 "could not link pay0 to rtspclientsink0"）→ 改为 `h264parse ! rtspclientsink`。
3. **源选择**：本机 UVC 摄像头 `gst-device-monitor` 推荐 **mfvideosrc**（Media Foundation）；
   dshowvideosrc/ksvideosrc 对该设备只吐 1 帧就停。改 `source_element` 让 auto 优先 mfvideosrc，
   并把源名与 `device-index=` 参数拆开（`element_available` 只认裸名）。
4. **退避伪成功**：gstreamer 后端在 `gst PLAYING` 时就报 STREAMING，但 rtspclientsink 异步连接，
   连不上会发 ERROR → 状态反复 STREAMING→DISCONNECTED 把 attempt 清零，1/2/5/10s 升不上去。
   在 `stream_controller` 加 `kStableGraceSec=3.0`：STREAMING 需稳定 ≥3s 才重置退避计数。

### 真实设备约束
- 本机只有一个 "UVC Control" 摄像头，**原生 240×240 @ 8fps**（非 webcam 默认分辨率），
  默认 1280×720@30 协商会失败 → 验收用 `--width 240 --height 240 --fps 8`。
- 编码器走 **nvh264enc**（N 卡 NVENC）；nvh264enc 不支持 I420（只 NV12/Y444/...），
  所以 caps 不能 pin format=I420，交由 videoconvert 协商。
- GIO 代理噪声：`giolibproxy.dll` 加载失败 + 本机 `HTTP_PROXY=127.0.0.1:7892` → 可达性探测偶报
  "not reachable"，但属软检查（仅告警，不影响实际重连）。

### 验收结果（确定性可复现，`scripts/e2e-test.ps1`）

- `--list` 真实枚举到摄像头。

## build_oneclick.bat / start-camera-agent.bat 真实修复（阶段 4，已实测通过）

### build_oneclick.bat（之前报错 "此时不应有 ." RC=255）
- 根因1：`echo [ERROR] Visual Studio not found (looked in '%VSPATH%').` —— 括号内 echo 串里的 `)` 提前关掉
  `if not exist (...)` 块（cmd 不把引号内 `)` 当字面量），导致后面 `'.` 成为 "unexpected"，整文件解析失败。
  即使该 `if` 分支运行时被跳过，解析期仍报错。改法：echo 串去掉 `()`（改成 `- looked in %VSPATH%`）。
- 根因2：`%~dp0` 带尾反斜杠 → `cmake -S "%ROOT%"` 变 `"...carmera-agent\"`，`\"` 被 cmd 当成转义引号，
  cmake 把整行当成 -S 参数 → "source directory does not exist"。改法：`if "%ROOT:~-1%"=="\" set ROOT=%ROOT:~0,-1%` 去尾斜杠；
  并修 `set BUILD=%ROOT%\build-msvc` / `set EXE=%ROOT%\build-msvc\...`（去尾斜杠后必须显式补 `\`，否则拼成 `carmera-agentbuild-msvc` 兄弟目录）。

### start-camera-agent.bat（之前双击"没反应"）
- 双击 .bat 继承注册表系统 PATH，mediamtx/ffplay/ffmpeg 只在交互 shell 会话 PATH → 原来静默失败。
  改法：新增 `:add_tool_path` 探测 `D:\data\agent-tools\...` 已知目录并 prepend 到 PATH，双击也能跑。
- 同一 `)`-in-echo 陷阱：exe 预检块 `echo ... (or: build_oneclick.bat sim)` 的 `)` 提前关块，
  使 `goto :fail` 漏出块外**无条件执行** → 永远报 "exe not found"（实际 exe 存在）。去 `()` 后修。
  另两处同类隐患（`:need` 里 `(System Properties ...)`、验证块里 `(no camera / GStreamer issue?)`）一并去 `()`。
- **修正阶段3的错误结论**：`start "title" cmd /c prog > log` 的 `>` 落在 start 的 stdout 上，而 start 开新控制台窗，
  子进程输出根本不进文件 → 日志 0 字节（之前误以为"去内层引号就正常"其实是没捕获）。正确写法：
  `start "MediaMTX" cmd /c "mediamtx > %FINISHED%\mediamtx.log 2>&1"`（重定向放进 `cmd /c "..."` 内，路径无空格故不去内层引号）。
- `timeout /t 1` 在本沙箱被 Git Bash 的 GNU timeout 抢先（"invalid time interval '/t'"）→ 轮询 0 延迟。
  钉死 `C:\Windows\System32\timeout.exe /t 1`。
- 轮询 `for /l` 内 `goto :label` 会丢弃刚 `set` 的变量（cmd 已知怪癖）→ mediamtx 永远报 not ready。
  改法：去掉 goto，改用 `EnableDelayedExpansion` 标志位 `if "!MT_READY!"=="0" (...)` 轮询。

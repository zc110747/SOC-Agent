## 启动 joint 后 "全部 offline / no stream is available on path camera01" 根因

现象：`start-joint-ai.bat` 启动后 WebRTC 报 `webrtc signaling status 404: no stream is available on path 'camera01'`，
视频全 offline。

根因：**部署的 `camera-agent.exe` 是 SIM 编译后端**（backend 是 CMake 编译期宏 `CAMERA_AGENT_BACKEND`，非运行时旗标）。
- `src/rtsp/rtsp_publisher_sim.cpp` 的 `connect()` 只置 `connected_=true` 并打日志，**从不真正建立 RTSP 连接**；
- `src/pipeline/video_pipeline_sim.cpp` 的 `run()` 只在循环里累加 `frames` 计数，**不跑真实 GStreamer 管线、不向 MediaMTX 推流**。
- 所以 agent 日志显示 `Status: STREAMING / frames=2000+` 是假象；MediaMTX 收不到 camera01 发布 → WebRTC 自然 `no stream`。
- `auto` 仅在构建期检测到 GStreamer 时才解析为 gstreamer，否则回退 sim（之前构建环境没探测到 GStreamer → 产出 SIM 包）。

修复（已落地，待 build 验证）：
- `carmera-agent/scripts/build-msvc.ps1`：`-Backend gstreamer` 默认输出到 `build-msvc-gst`（与 SIM 的 `build-msvc` 分离）；
  构建后从 `CMakeCache.txt` 读 `CAMERA_AGENT_BACKEND` 写 `<BuildDir>/backend.txt` 标记。
- `video-server/scripts/start-joint-ai.bat` 与 `start-joint.bat`：优先用 `build-msvc-gst` 的 GStreamer 包；
  读 `backend.txt`，若为 `sim` 则**显式警告**"SIM 不推流 → WebRTC 会报 no stream"，并给出重建命令。
- 真正要看到视频+AI 框：必须用 **GStreamer 后端**构建（`scripts\build-msvc.ps1 -Backend gstreamer`）+ 本机有 UVC 摄像头；
  SIM 仅用于无摄像头 headless 联调编排/重连逻辑，永远不会有实时画面。

## 修复 WebRTC 频繁点击偶发复位 + 彻底移除网页端 HLS（2026-09-04 同一会话）

### 缺陷 1：频繁点击 WebRTC 偶发复位
- 根因：`useWebRTC()` 直接 `connectWebRTC()`，快速连点会并发多个 `RTCPeerConnection` 实例互相竞争；
  旧的 watchdog 超时还会在切换中途调用 `startHLS()` 把元素切走，表现为"复位 / 黑屏"。
- 修复（`web/src/webrtc/player.ts`）：引入**代际令牌 `token`** + `switching` 防重入。
  `useWebRTC()` 三阶段：① `cancelAll()` 回退到关闭态（`transport=null`、拆 peer、清定时器）；
  ② `token++` 使任何在途异步（offer/answer/ontrack/onconnectionstatechange）在下次 `await` 后
  因 `myToken !== this.token` 直接 abort → 内部数据与此模式一致后再更新；③ 才 `connectWebRTC(myToken)`。
  所有回调/超时/重试均带 `myToken` 一致性校验，旧连接绝不会污染新连接。
- 失败不再降级 HLS：`onWebRTCFailure` 仅 `scheduleReconnect`（有界延时，持续重试 WebRTC）。
- 状态枚举精简：`PlayerState` 去 `fallback`；`Transport` 仅 `'webrtc' | null`。

### 缺陷 2：彻底移除网页端 HLS（保留 video-server 端 HLS 能力，不动 Go）
- 移除显示入口：`VideoPlayer.vue` 删 "HLS" 按钮；`transportLabel` 去掉 "HLS (fallback)"（仅 WEBRTC/—）；
  `stateText` 去 `fallback` 分支；模板/注释里 HLS 字样清掉。
- 移除失败自动切换逻辑：`player.ts` 删 `useHLS`/`startHLS`/`scheduleHLSRetry`/`teardownHLS`、
  `hls` 字段、`import Hls from 'hls.js'`、`WEBRTC_TIMEOUT_MS` 里 HLS 注释、`watchdog→startHLS`、
  `onWebRTCFailure` 的 `MAX_WEBRTC_ATTEMPTS`→HLS 分支。
- `web/package.json` 删 `hls.js` 依赖。
- `client.ts` 的 `StreamInfo.hls_url/hls_direct_url` 字段保留（服务端仍返回，属 API 契约；网页不再展示/使用）。

### 验证
- `npm run build`（vite v5）零错误；`video-server.exe` 重建已嵌入新 web。
- live 冒烟：server health 200、index 200；**服务端 bundle 中 `useHLS` 出现 0 次** → HLS 逻辑确已剔除。
- 未动 Go 代码，`go build`/aimode 接口无回归（默认仍走 ai-y-pose 因上一 e2e 落库值）。

## 修复切换 AI 模式时"多个框"重叠（2026-09-04 同一会话）

### 现象
点击切换 AI 模式（detect↔pose）时画面出现多个/多余框（绿框与黄骨架线并存）。

### 根因
agent 收到 web 的 `POST aimode` 后需 ~1s 才完成 detector 热替换，期间仍发**上一个模型**的帧。
旧 `pollMetadata` 仅按物体形状绘制：detect→pose 切换中仍把旧 detect 帧画成绿框；
pose→detect 切换中仍因 `o.keypoints.length===17` 画出黄骨架线 —— 即"中间帧"被合成了。

### 修复（`web/src/components/VideoPlayer.vue`，纯前端）
- `selectAIMode()` 点击即调 `closeOverlayNow()` **立刻清空 overlay**（优先关闭显示框）。
- 新增 `dataModeOf(snap)`：帧含 17 关键点→`ai-y-pose`，仅 bbox→`ai-y`，无物体→`none`。
- `pollMetadata()` 在 `ai-off` 之后、`draw` 之前：若 `dataMode !== aiMode`（且非 `none`）
  即判定为切换中的"中间帧"，`clearOverlay` 并 **丢弃**（不绘制），直到到达与当前模式匹配的数据
  才做 UI 合成显示。骨架仅在 pose 模式且数据确为 pose 时绘制。
- 仅改前端，agent / video-server Go 端不动。

### 验证
- `npm run build` 零错误；`video-server.exe` 重建已嵌入新 web；live 冒烟 server health 200 / index 200。
- 视觉观感（连点切换不再叠框）建议在真机浏览器最终人工确认一次（逻辑已在代码层确保）。

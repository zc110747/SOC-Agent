## 修复 scripts/start-joint.bat 无法一键启动

### 症状
双击 `scripts/start-joint.bat` 后 `video-server` 起不来，日志停在：
`ERROR server error: start mediamtx: mediamtx binary not found at "mediamtx.exe"`

### 根因（主因）
**跑了旧二进制**。exe 是 9/1 10:03 编的，而 `internal/mediamtx/manager.go` 9/2 08:31 改过 ——
`findBinary()` 已升级为三级回退（配置值 → `mediamtx/mediamtx.exe` → `exec.LookPath("mediamtx")`），
但从未重新构建。判定依据：日志里的报错文案 `mediamtx binary not found at "%s"` 在当前源码里
已经 grep 不到（现为 `mediamtx binary not found; tried [%s]`）。

mediamtx.exe 本身一直在系统 PATH（`D:\data\agent-tools\mediamtx_v1.20.1_windows_amd64`），
新逻辑走 `exec.LookPath` 即可找到，重建后立刻恢复。

### 修法
1. `go build -trimpath -o video-server.exe ./cmd/video-server`（无 `go:embed`，Web UI 是
   `web/dist` 磁盘直出，所以不需要跑 npm，单编 Go 即可）。
2. 给 `start-joint.bat` 加**源码/二进制 mtime 比较 + 自动重建**（防复发）。

### 顺带修掉的两个 .bat bug
- **坑：cmd 不剥离双引号内的 `^`**。原 LAN IP 探测用
  `powershell -Command "(Get-NetIPAddress ... ^| Where-Object {...})"`，`^|` 位于 `-Command "..."`
  的双引号内 → `^` 原样传给 PowerShell → `找不到接受实际参数"^"的位置形式参数`。
  改为**无管道**写法：`Invoke-RestMethod http://localhost:<port>/api/net/addresses` 取 `public_host`。
  附带收益：直接复用服务端 `netiface` 的排序（物理网卡优先，VMware/WSL/Hyper-V/vEthernet 靠后），
  打印的 IP 与 RTSP/WebRTC URL 播发的一致（本机 = `192.168.16.52`，而非 `172.17.176.1` 虚拟网卡）。
- **坑：`if (...)` 块内 echo 文本含成对括号**。新写的 `echo (from GET /api/net/addresses)`
  被解析成嵌套块 → `此时不应有 ---。`。去掉块内括号解决。

### 本轮新踩的 .bat 坑（已写进 skill `soc-debug-verification`）
1. **findstr 的 `$` 锚点在管道下失效**：`(echo 8081) | findstr /r "^[0-9][0-9]*$"`
   判 8081 为非法！`$` 不吃掉 echo 输出的 CR。改 `set /a "PORT_NUM=%HTTP_PORT%"` 回环比对
   （数字原样返回，非数字不等）+ `LSS 1 / GTR 65535` 范围检查。
2. **`--config` 路径前缀拼接**：脚本内部固定拼 `config\%CFG_NAME%`，用户传
   `--config config\config.yaml` 会变成 `config\config\config.yaml`。修法：三级探测
   `ROOT\config\<name>` → `ROOT\<name>` → `<name>`（绝对/相对路径都吃），并把实际解析出的
   相对路径单独存 `CFG_ARG` 传给服务端（服务端 CWD 是 ROOT）。
3. **node_modules 存在 ≠ 依赖完整**：`hls.js` 是后加进 package.json 的，node_modules 停在旧时间，
   Vite 直接 `Rollup failed to resolve import "hls.js"`。对策：build 失败自动 `npm install` 后重试一次。

## 环境备注
- **沙箱会回收跨调用启动的进程**：PowerShell/Bash 工具调用里 `start` 拉起的进程会在调用结束后
  若干分钟内被清掉。要在调用间隔里做 HTTP 验证，必须**在同一次 Bash 调用内**起进程 + 发请求。
- PowerShell 工具**禁止** `cmd.exe` 和 `[Diagnostics.Process]::Start`；且原生命令写 stderr 会让
  PowerShell 报 exit 1（假象），所以要判脚本真实退出码，用一个 wrapper .bat（
  `call 目标.bat %*` 后 `echo EXITCODE=%errorlevel%`）最可靠。
- 一次 PowerShell 调用里连续 `&` 跑两个 .bat 时，**第二个常不执行**（前一个非零退出即中断）。
  分成两次调用。
- `rm -f` 批量删文件偶发 SIGTERM（部分删除成功）；改用 PowerShell `Remove-Item -LiteralPath` 逐个删。
- PowerShell `>` 落盘是 **UTF-16**，用 `python -c "...decode('utf-16')"` 读。
- 服务被回收后 `localhost:8081` 会返回 **502 `upstream connect failed`**（沙箱代理），
  不要误判成应用故障；用 `tasklist` 或直接重启确认。
